# tcp-kai

Десктопный клиент для NestJS-микросервисов по TCP (Tauri 2 + React 19)
и CLI `tcp-kai` поверх того же ядра (внутри бандла — sidecar `tcp-kai-cli`).
Коллекция = микросервис, запрос = сохранённый паттерн (`cmd`) с JSON-телом,
пак переменных = стенд (`local`/`prod`/…).

## Установка (macOS, Apple Silicon)

### Homebrew

```bash
brew install kaidstor/tap/tcp-kai
```

Каск ставит приложение и CLI `tcp-kai` в PATH.

### Вручную (.dmg)

1. Скачайте `.dmg` из [последнего релиза](https://github.com/Kaidstor/tcp-kai/releases/latest) и перетащите tcp-kai в Applications.
2. Приложение подписано Developer ID и нотаризовано Apple (с v1.3.4) — Gatekeeper не блокирует запуск, но при первом открытии macOS один раз спросит подтверждение («приложение скачано из интернета»): нажмите Open.

   Сборки **до v1.3.4** подписаны dev-сертификатом и не нотаризованы — их macOS блокирует наглухо («приложение повреждено» / «не удаётся проверить разработчика»). Обход: System Settings → Privacy & Security → **Open Anyway**, либо снять карантин командой:

   ```bash
   xattr -dr com.apple.quarantine /Applications/tcp-kai.app
   ```

3. Дальше приложение обновляется само: updater качает релизы с GitHub (тост о новой версии, «Check for Updates…» в меню), после обновления показывается «Что нового» с историей версий. Установленные версии ≤1.3.4 продолжают читать манифест с GitLab — зеркало latest.json там публикуется, пока такие клиенты живы.

CLI `tcp-kai` лежит внутри бандла — пункт меню **tcp-kai → Install CLI…** делает симлинк в PATH, и CLI обновляется вместе с приложением. То же руками — `./scripts/install-cli.sh`.

### Скилл для AI-агентов

В репозитории есть скилл `tcp-kai` ([skills/tcp-kai/SKILL.md](skills/tcp-kai/SKILL.md)) по спецификации [Agent Skills](https://agentskills.io) — инструкции агенту, как дёргать микросервисы через CLI. Установка (CLI сам спросит, в какого агента и куда — в проект или глобально):

```bash
npx skills add https://github.com/Kaidstor/tcp-kai --skill tcp-kai
```

## Стек

- **Backend**: Rust, tokio (TCP-обмен с таймаутами и отменой), SQLite через `tauri-plugin-sql` / `sqlx` — одна база у GUI и CLI, regex-парсер NestJS-контрактов (`*.contract.ts`).
- **Frontend**: React 19, Vite 8, Tailwind CSS v4, zustand, CodeMirror 6 (`lang-json` в редакторе, `@codemirror/merge` в диффе).

## Возможности

- Модель данных: **коллекция = микросервис**, **запрос = NestJS-паттерн** (`cmd`) с телом, **пак переменных = стенд** — в паке лежат `host`/`port` и прочее для подстановки `{{var}}` в адрес и тело. Паки бывают локальные для коллекции и глобальные (видны отовсюду).
- База — SQLite `~/Library/Application Support/com.kaidstor.app/app.db`, общая с CLI: отправка из консоли попадает в ту же историю и поднимает запрос в сайдбаре GUI. База не шифруется — секреты в паках не хранить, для них есть интеграция с `sec` в CLI.
- Редактор тела с подсветкой и линтом JSON, сплит запрос/ответ (горизонтальный или вертикальный), ⌘⏎ — отправить, отмена зависшего запроса, настраиваемый таймаут ответа (по умолчанию 60 с, 0 — без лимита).
- История обменов на каждый запрос (лимит настраивается, по умолчанию 200 записей): флаг ok, фактический адрес и пак на момент отправки; любые две записи можно сравнить в диффе (`@codemirror/merge`, красное — было, зелёное — стало).
- Command-палитра: ⌘P — коллекции и их действия, ⌘K — запросы, ⌘E — паки переменных, ⌘, — настройки. Создание/переименование коллекций и запросов — там же.
- Прод-предохранитель: пак с `prod`/`live`/`боев` в имени подсвечивается красным, write-запросы (`create-*`/`update-*`/`delete-*`/`send-*`) на такой пак требуют явного подтверждения.
- Раннер: прогнать выбранные запросы коллекции подряд и получить таблицу исходов (smoke после деплоя). По умолчанию отмечены только read-запросы, историю прогон не трогает.
- Импорт контрактов: перетащить `*.contract.ts` в окно (или ⌘P → «Импортировать контракт») — из as-const объекта/enum с `*Cmd*` или контроллера с `@MessagePattern` создаются запросы; существующие не трогаются, `@deprecated` пропускаются.
- Темы (тёмные и светлые) как наборы CSS-переменных поверх Tailwind; кастомный тайтлбар (`titleBarStyle: Overlay`): traffic lights поверх приложения, в полосе — текущая коллекция, переключатель стенда и история.

## Протокол: как это работает

Кадр NestJS TCP-транспорта: `<число_символов>#{json}`, внутри — `pattern`, `data` и `id`. Ответ читается до конца кадра; конверт транспорта (`response`/`err`/`isDisposed`) разворачивают уже GUI и CLI — с тумблером raw, если нужен ответ как есть.

- `@MessagePattern` — обычный request/response; connect-таймаут 5 с, ответа ждём 60 с (настраивается, 0 — вечно).
- `@EventPattern` — кадр без `id`, ответ не ждём (в CLI — флаг `--emit`).
- Ядро (`src-tauri/src/tcp.rs`) не знает про Tauri: GUI-команды и CLI используют один и тот же код, проволока и разбор ответа не разъезжаются.

## CLI `tcp-kai`

Консольный клиент поверх того же Rust-ядра (отдельный бинарь, cargo-фича `cli`):
коллекции, паки, история — общие с GUI. Подробная документация — в скилле
[skills/tcp-kai/SKILL.md](skills/tcp-kai/SKILL.md).

```bash
tcp-kai ls                                  # какие микросервисы заведены (+ применённый пак)
tcp-kai ls coordinator                      # запросы сервиса (имя и cmd, если отличается)
tcp-kai envs coordinator                    # паки переменных и что в них лежит
tcp-kai history coordinator auth-login      # последние обмены (--full — с телами, --json)

tcp-kai coordinator auth-login              # отправить (= tcp-kai send …; пак — применённый в GUI)
tcp-kai coordinator auth-login -e local     # тот же запрос на другой стенд (состояние GUI не меняет)
tcp-kai whois lookup --json | jq .response  # машинночитаемо: в stdout только ответ сервиса
tcp-kai coordinator sync --timeout 300      # долгий запрос (сек; 0 — ждать вечно)
tcp-kai notifier user-created --emit        # @EventPattern: кадр без id, ответ не ждать

tcp-kai parse  ../whois/src/contracts/cmd.contract.ts       # что найдётся в контракте (без базы)
tcp-kai import whois ../whois/src/contracts/cmd.contract.ts # создать новые запросы (--dry-run)
tcp-kai daemon status                       # keep-alive-демон: пул соединений (stop, run)
tcp-kai completions zsh                     # шелл-дополнения
```

Ключевое:

- Первый аргумент, не являющийся подкомандой, читается как имя коллекции.
  Запрос ищется по имени, затем по `cmd`, регистр не важен; при опечатке CLI
  сам покажет похожие имена.
- **Тело** по умолчанию едет сохранённое в приложении; разово перекрывается
  через `-d '{...}'`, `-f body.json` или stdin — сохранённое в базе при этом
  не перезаписывается (в отличие от GUI, где редактор — источник правды).
- **Переменные** — по цепочке, каждый следующий источник перекрывает
  предыдущий: пак из базы (`-e`, иначе применённый в GUI) → `sec`
  (только с `--from-sec`) → `--var key=value`; `--url host:port` — мимо пака
  целиком. Неизвестное имя остаётся в тексте как `{{name}}` — опечатка видна;
  неразрешённый `{{...}}` в адресе — отказ идти в сеть с объяснением.
- **Секреты через [sec](https://github.com/Kaidstor/sec)** (агент-безопасный
  менеджер секретов), в базе приложения они не хранятся. Конвенция: коллекция
  `coordinator` → sec-проект `tcp-kai-coordinator`, пак `prod` → инстанс
  `-e prod`, `{{token}}` → ключ `TOKEN`. Тянутся только ключи, упомянутые в
  запросе; значения идут через stdout дочернего процесса, не через argv;
  в историю тело пишется **до** подстановки — секрет в базу не уезжает.
- История пишется как в GUI (включая ошибки; ответ сервиса — как есть),
  обрезается по лимиту из настроек; `--no-history` — не писать,
  `-v` — трассировка кадра в stderr (после подстановки — с живым секретом).
- **Keep-alive-демон**: соединение не переживает процесс CLI, поэтому `send`
  сам поднимает фоновый демон (аналог ssh ControlMaster) и ходит через него по
  unix-сокету — последовательные вызовы и скрипты из CLI-запросов
  переиспользуют TCP-соединение (метка `⟳` в сводке). GUI ходит через того же
  демона (нет живого — поднимает его потоком внутри себя), так что пул общий:
  кто первый занял сокет, того пулом и пользуются оба. Простаивающее
  соединение живёт 60 с, демон без запросов выходит через 15 мин; соединение,
  закрытое сервером в простое, прозрачно передёргивается (retry только если
  отказ случился до первого байта ответа и не по таймауту — иначе запрос мог
  быть уже принят в работу). Отмена запроса — разрыв клиентского сокета:
  демон бросает обмен, соединение в пул не возвращается (так работает отмена
  из GUI). `tcp-kai daemon status/stop/run`, обход — `--no-daemon` или
  `TCP_KAI_NO_DAEMON=1`; `-v` всегда идёт напрямую, чтобы трасса печаталась
  в терминал. Демон недоступен — запрос молча едет напрямую.
- `TCP_KAI_DB` переопределяет путь к базе (тесты на копии),
  `TCP_KAI_SEC_BIN` — бинарь sec (иначе из PATH), `TCP_KAI_DAEMON_SOCK` —
  сокет демона, `TCP_KAI_DAEMON_TTL`/`TCP_KAI_DAEMON_IDLE_EXIT` — его тайминги
  в секундах.

Установка:

```bash
# из установленного приложения: меню tcp-kai → Install CLI… (симлинк в бандл,
# обновляется вместе с приложением), либо ./scripts/install-cli.sh

# из исходников
cd src-tauri && cargo build --release --features cli --bin tcp-kai-cli

# готовый бинарь из GitHub-релиза (macOS arm64; собирает и грузит release.sh)
curl -fL https://github.com/Kaidstor/tcp-kai/releases/latest/download/tcp-kai-cli-darwin-aarch64.tar.gz \
  | tar xz -C /usr/local/bin
```

## Запуск

```bash
bun install
bun run tauri dev     # разработка
bun run tauri build   # сборка .app/.dmg

# локальный релиз: бамп версии, сборка, подпись, нотаризация, GitHub-релиз
# (артефакты автообновления + tcp-kai-cli-darwin-aarch64.tar.gz, бамп каска,
# зеркало latest.json в GitLab для клиентов ≤1.3.4).
# APPLE_PASSWORD хранится в sec — без него tauri молча пропустит нотаризацию
# (релизный скрипт это ловит и не даёт опубликовать ненотаризованный бандл)
sec run apple --only APPLE_PASSWORD -- ./release.sh
```
